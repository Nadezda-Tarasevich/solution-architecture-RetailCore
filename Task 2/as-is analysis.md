# Краткий анализ артефактов, использованных для восстановления текущего состояния RetailCore

Для восстановления AS-IS архитектуры платформы RetailCore были проанализированы следующие артефакты:



|**Артефакт<br />**|**Что дал<br />**|**Ограничение<br />**|
|-|-|-|
|Описание компании <br />|Понимание исторического контекста: система не проектировалась как единая платформа, а развивалась шаг за шагом. Идентификация ключевых областей: оформление, обработка, статусы, логистика, финансы. Технологический стек: Java + Oracle + Python/.NET. Инфраструктурные ограничения: on-premise, физические серверы<br />|Давал формальную картину, которая, как выяснилось из интервью, расходится с реальностью<br />|
|5 стенограмм интервью (спонсор, поддержка, техлид монолита, разработчик интеграций, разработчик аналитики)<br />|90% информации о реальном устройстве системы, проблемных зонах, скрытых зависимостях и поведении системы. Каждый стейкхолдер раскрыл свою часть картины<br />|Субъективность — каждый видит систему со своей точки зрения. Требовалась кросс-валидация<br />|
|Фрагмент кода OrderProcessingService<br />|Конкретные примеры проблем: смешение ответственности в одном методе, интеграция через staging-таблицы, fallback на Oracle-процедуры, retry через таблицу, синхронные вызовы|Всего один метод. Полная картина требует анализа всего репозитория<br />|
|Исходная PlantUML-диаграмма<br />|Отправная точка для визуализации: внешние системы, монолит, Oracle, периферийные сервисы<br />|Была неполной и неточной. Потребовались множественные итерации исправлений<br />|



Ключевые выводы сделанные из анализа артефактов:

Система не является единой

Реальность сложнее формальной схемы

Монолит остаётся точкой управления

Oracle содержит процедуры с логикой



Вывод: Наиболее ценным артефактом оказались интервью со стейкхолдерами (50% информации). Фрагмент кода подтвердил и конкретизировал проблемы. Исходная UML дала отправную точку, но потребовала значительной переработки. Для полного восстановления архитектуры потребуется анализ всего репозитория монолита и полный каталог Oracle-процедур.
